# Native Maps SDKs - 300.x, 200.x and Runtime 100.x

The ArcGIS Maps SDKs for Native Apps come in generations whose code and documentation trees differ. Identify the generation of the user's project first. `arcgis_docs_get_versions` reports exact releases; this brief explains the lines.

| Line                 | State                               | Documentation                       |
| -------------------- | ----------------------------------- | ----------------------------------- |
| 300.x                | current; new features               | `developers.arcgis.com/<sdk>/`      |
| 200.x                | bug fixes and security updates only | `developers.arcgis.com/<sdk>/v200/` |
| ArcGIS Runtime 100.x | long-term support line near its end | Esri's archive host: link only      |

- `<sdk>` is `swift`, `kotlin`, `net`, `qt` or `flutter`. The tree without a prefix is the newest line, and its home page links to the older one ([Kotlin](https://developers.arcgis.com/kotlin/)).
- The 200.x home pages state the policy: fixes only, while 300.x builds on the same architecture ([.NET 200.x](https://developers.arcgis.com/net/v200/)). Going from 200.x to 300.x is an upgrade, not a rewrite; read the 300.x release notes of the SDK.
- Pass `version: "v200"` to the tools to read the 200.x tree. A page may be missing or different in the other tree.

## Java

ArcGIS Maps SDK for Java is deprecated and ended at 200.6. It has no 300.x line and is documented only under [`/java/v200/`](https://developers.arcgis.com/java/v200/). Esri tells developers to move to another native SDK or another ArcGIS technology ([notice](https://support.esri.com/en-us/knowledge-base/deprecation-arcgis-maps-sdk-for-java-000032164)). The ArcGIS Enterprise SDK, which also uses Java, is a separate product and unaffected.

## Runtime 100.x

- Named "ArcGIS Runtime SDK for Android / iOS / .NET / Qt / Java".
- At 200.0 the Android and iOS SDKs were redesigned as the Kotlin and Swift SDKs. Coming from 100.x is a migration with API changes (coroutines and flows in Kotlin, async/await and SwiftUI in Swift): follow the migration page for [Kotlin](https://developers.arcgis.com/kotlin/reference/migrate-from-100-x-to-200-x/) or [Swift](https://developers.arcgis.com/swift/reference/migrate-from-100-x-to-200-x/).
- Never paste 100.x snippets into a 200.x or 300.x project. A typical sign on iOS is the `AGS` class prefix (`AGSMap`, `AGSMapView`), which the Swift SDK dropped.

## Checking the project

- Kotlin: Maven artifact `arcgis-maps-kotlin`. Swift: package `arcgis-maps-sdk-swift`. .NET: NuGet `Esri.ArcGISRuntime` and its platform packages. Flutter: pub package `arcgis_maps`.
- Sample repositories are tagged per release; the Qt and Flutter repositories also carry pre-release build tags. Use the tag matching the installed version, not the newest tag.

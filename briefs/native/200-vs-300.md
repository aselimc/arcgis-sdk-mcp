# Native Maps SDKs - 300.x, 200.x and Runtime 100.x

The ArcGIS Maps SDKs for Native Apps (Swift, Kotlin, .NET, Qt, Flutter, Java) exist in three generations. Code, package names and documentation trees differ between them, so identify the generation in the user's project before reading or writing anything. `arcgis_docs_get_versions` reports the exact current releases; this brief only explains the lines.

## The lines

| Line | State | Documentation |
| --- | --- | --- |
| 300.x | current line; new features land here | `https://developers.arcgis.com/<sdk>/` |
| 200.x | bug fixes and security updates only | `https://developers.arcgis.com/<sdk>/v200/` |
| ArcGIS Runtime 100.x | long-term support release in its final phase, then retired | Esri's archive host, which this server links to but does not read |

- `<sdk>` is `swift`, `kotlin`, `net`, `qt` or `flutter`. The un-prefixed tree is always the newest line, and each home page links to the older one ("Looking for 200.x?" on [Kotlin](https://developers.arcgis.com/kotlin/)).
- The 200.x home pages state the policy: 200.x is limited to fixes, and 300.x builds on the same architecture ([.NET 200.x home](https://developers.arcgis.com/net/v200/)). Moving from 200.x to 300.x is an upgrade, not a rewrite: read the release notes of the 300 releases for the SDK.
- In tool calls pass `version: "v200"` (or a 200.x number) to read the 200.x tree. A page that exists in one tree may be missing or different in the other.

## Java is the exception

ArcGIS Maps SDK for Java is deprecated and stopped at 200.6; it has no 300.x line and its documentation lives only under [`/java/v200/`](https://developers.arcgis.com/java/v200/). Esri tells desktop developers to move to another native SDK or another ArcGIS developer technology ([deprecation notice](https://support.esri.com/en-us/knowledge-base/deprecation-arcgis-maps-sdk-for-java-000032164)). Do not start new work on it. The ArcGIS Enterprise SDK, which also uses Java, is a different product and is not affected.

## Runtime 100.x

- Names: "ArcGIS Runtime SDK for Android / iOS / .NET / Qt / Java". Renamed to ArcGIS Maps SDKs at 200.0.
- Android and iOS were re-designed at 200.0 as the Kotlin and Swift SDKs. Coming from the Java-based Android SDK or the Objective-C/Swift iOS SDK is a migration with API changes (coroutines and flows on Kotlin, for example): follow [Migrate from 100.x to 200.x](https://developers.arcgis.com/kotlin/reference/migrate-from-100-x-to-200-x/) and the equivalent page of the target SDK.
- Never copy 100.x snippets into a 200.x or 300.x project. A typical tell on iOS is the `AGS` class prefix (`AGSMap`, `AGSMapView`), which the Swift SDK dropped ([Swift migration page](https://developers.arcgis.com/swift/reference/migrate-from-100-x-to-200-x/)).

## Checking the project

- Kotlin: Maven artifact `arcgis-maps-kotlin`. Swift: package `arcgis-maps-sdk-swift`. .NET: NuGet `Esri.ArcGISRuntime` and its platform packages. Flutter: pub package `arcgis_maps`.
- Sample repositories are tagged per release, and the Qt and Flutter repositories also carry pre-release build tags. Use the tag that matches the installed version, not the newest tag.
